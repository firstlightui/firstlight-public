# Firstlight UI — public website

The marketing site, documentation, and component gallery for [Firstlight UI](https://github.com/firstlightui/nativephp), the app-shell layer for NativePHP.

This repository is **the website only**. The Firstlight package itself — the Blade components, the SwiftUI and Jetpack Compose renderers, the `ValidatesFields`, `SubmitsForms`, `AuthorizesActions`, `PaginatesLists`, and `DestroysListItems` concerns, and the docs this site renders — lives in [`firstlightui/nativephp`](https://github.com/firstlightui/nativephp).

## What Firstlight is

Firstlight is the app-shell layer for [NativePHP](https://nativephp.com). `composer require firstlightui/nativephp` plus Laravel Boost gives a developer, or their coding agent, what a standard forms app needs: lists and detail, search, forms with Laravel validation, settings, sheets and dialogs, and feedback. Every control is a genuine SwiftUI or Jetpack Compose control. Navigation chrome comes from NativePHP's native chrome (`usesNativeChrome()`) and layout from Mobile UI; Firstlight does not replace either. It is not a design system and has no charts or carousels.

The site leads with the four recipes, the Boost guideline and skills, and accessibility. Keep its claims to what the package's code and CHANGELOG support; Firstlight 1.0.0 is stable and was tested on physical devices, including VoiceOver on iOS; spoken TalkBack and long-running performance tests are not recorded.

It runs on the SuperNative foundation created by [Shane Rosenthal](https://github.com/shanerbaner82) and [Simon Hamp](https://github.com/simonhamp).

To use Firstlight in an app:

```bash
composer require firstlightui/nativephp
```

## Running this site locally

Requires PHP 8.3+, Composer, and Node.

```bash
composer setup   # install deps, create .env, generate key, migrate, build assets
composer dev     # run the app, Vite, queue worker, and logs together
```

`composer setup` is idempotent — it will not overwrite an existing `.env`.

## Checks

```bash
composer test          # config clear + Pint + PHPStan + Pest
composer lint          # Pint, fixing in place
composer lint:check    # Pint, dry run
composer types:check   # PHPStan (Larastan)
```

CI runs `composer setup` then `composer ci:check`, which is the same suite as `composer test`. Run it before opening a pull request.

## How the site is put together

| Route | Source |
|---|---|
| `/` | `resources/views/welcome.blade.php` |
| `/components` | `resources/views/components/index.blade.php`, driven by `config/component-gallery.php` |
| `/firstlight-vs-nativephp-mobile-ui` | `resources/views/comparison.blade.php` |
| `/docs/{path?}` | Markdown fetched live from GitHub by `App\GitHubDocumentation` |
| `/{section}/{page}` | 301 to `/docs/{section}/{page}` for `getting-started`, `how-to`, `concepts`, `reference`, and `components`, because RC6 Boost guidelines and `llms.txt` linked docs without `/docs` |
| `/llms.txt` | Docs index, generated by `LlmsTextController` |
| `/llms-full.txt` | Full text of every docs page, generated by `LlmsFullTextController` |
| `/sitemap.xml` | Marketing pages plus every docs page, generated by `SitemapController` |
| `/robots.txt` | Generated by `RobotsController` — **not** a static file |
| `/pricing.md` | Machine-readable pricing, generated by `PricingController` |

### Discoverability

The site is built to be read and cited by AI assistants, since that is how much of its audience finds Laravel and NativePHP packages. Five things follow from that and should not be broken casually:

- **`robots.txt` is a route, not a file in `public/`.** It is generated so the `Sitemap:` line resolves to whatever host the app runs on, and it explicitly allows the search-and-cite crawlers (GPTBot, PerplexityBot, ClaudeBot, Google-Extended, Bingbot, Applebot). Nothing is disallowed.
- **`llms-full.txt` inlines every docs page** so an assistant can read the whole library in one request instead of crawling.
- **JSON-LD** is built in `App\StructuredData` and passed to the layout's `schema` prop — `SoftwareApplication` and `Organization` on the home page, `ItemList` on `/components`, `TechArticle` and `BreadcrumbList` on docs pages. It must stay literally true: no `aggregateRating`, `reviewCount`, or install counts while the project has no users. A test enforces this.
- **Every page is server-rendered** with semantic HTML and a clean accessibility tree. Agents read the DOM and the accessibility tree, so this is a functional requirement, not only an a11y one.
- **`pricing.md` exists because Firstlight is free.** Agents filter out products whose cost they cannot determine, and "free" only helps if it is legible without rendering a page. Keep it accurate if that ever changes.
- **The comparison page's FAQ is one array.** `$faqs` in `comparison.blade.php` feeds both the visible `<dl>` and the `FAQPage` JSON-LD, so the two cannot drift. A test asserts every schema question also appears in the body — never add a question to the schema that a reader cannot see.

### Open Graph image

`public/og.png` (1200×630) uses the showcase app's sunrise icon. The current
image is rendered from `resources/og-image.html` with the commands below. To render it after a brand or message
change, serve the repository root over HTTP so the shared icon resolves:

```bash
npx --yes http-server . -p 8899 &
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --window-size=1200,630 --force-device-scale-factor=2 --virtual-time-budget=8000 \
  --screenshot=/tmp/og@2x.png http://127.0.0.1:8899/resources/og-image.html
magick /tmp/og@2x.png -resize 1200x630 -strip public/og.png
```

It is rendered at 2x and downscaled so the type stays crisp. The fonts come from Google Fonts at render time, so the machine needs network access.

`tests/Feature/AiDiscoverabilityTest.php` covers all of the above.

### Documentation

Docs are **not** stored in this repository. `App\GitHubDocumentation` reads the `docs/` directory of the package repo through the GitHub API, parses front matter, renders Markdown, and builds the navigation, previous/next links, and `llms.txt`. Pages appear in the order `docs/index.md` links them, grouped under the index's `##` headings; pages the index does not list are grouped by directory. Responses are cached with `Cache::flexible` — fresh for 15 minutes, served stale for up to 24 hours while revalidating.

Configured in `config/documentation.php`:

| Variable | Default |
|---|---|
| `DOCUMENTATION_GITHUB_REPOSITORY` | `firstlightui/nativephp` |
| `DOCUMENTATION_GITHUB_BRANCH` | `main` |
| `DOCUMENTATION_GITHUB_PATH` | `docs` |
| `DOCUMENTATION_CACHE_FRESH_SECONDS` | `900` |
| `DOCUMENTATION_CACHE_STALE_SECONDS` | `86400` |

To edit documentation, open a pull request against `firstlightui/nativephp`, not this repository. If GitHub is unreachable the docs routes degrade to a 503 rather than failing hard.

### Component gallery

`config/component-gallery.php` lists every component shown on the home page carousel and the `/components` index — slug, title, Blade tag, availability, summary, and screenshots. Screenshots are pulled from the package repository at a pinned revision (`source_revision`), one pair per platform per theme: iOS and Android, light and dark.

The `sync-component-gallery` skill in `.agents/skills/` regenerates this file from the package repo. Bump `source_revision` when new screenshots land upstream.

### Theming

Light and dark themes are both first-class. `public/theme.js` sets the initial theme before paint to avoid a flash; the palette is dawn-led warm accents over technical neutrals, defined as `--site-*` custom properties in `resources/css/`. Design intent is recorded in `.impeccable.md`.
